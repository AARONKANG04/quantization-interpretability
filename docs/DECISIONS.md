# Decisions

Append-only. Each entry: date, decision, evidence file or reason.

- 2026-10-04: Primary model is google/gemma-3-4b-pt (text-only path); IT model only for the transfer test. Reason: Gemma Scope 2 SAEs were trained on it and few-shot evaluation is standard. May switch to IT at gate G0.1 if the PT GSM8K baseline is too low to measure loss cleanly.
- 2026-10-04: Primary damaging condition is Q1 = NVFP4 round-to-nearest W4A16 by our own QDQ, pending gate G0.1; FP8 per-channel (Q3) is the mild contrast. Embeddings, norms and lm_head stay bf16.
- 2026-10-04: Scope is LEAN, resume-first (plan doc section 1a); extended experiments only after the lean scope is complete. Reason: Aaron's call on the budget.
- 2026-10-04: Delivery is a sprint on an 8x H100 instance with Aaron alongside, starting 2026-10-05; kernel validation on the RTX PRO 6000 deferred past the sprint, with the bit-exact match against llm-compressor's NVFP4 quantizer standing in.
- 2026-10-05: Gate G0.2 proxy PASSED. qi.quant.nvfp4 reproduces llm-compressor's NVFP4A16 export bit-for-bit on all 238 matrices (results/phase0/crosscheck.json) after matching three details of its arithmetic: per-tensor global scale = 2688 * (1/amax) evaluated in bf16; block scale = (block max / 6) in bf16, times the fp32 global scale, cast to E4M3; q/k/v and gate/up share one global scale per layer (vLLM fuses those GEMMs). Element rounding is round-to-nearest with ties to the even FP4 code. Q1 and C2 checkpoints were rebuilt with the exact quantizer before any evaluation of Q1.
- 2026-10-05: Mechanism note from the pilot: across all 238 matrices, 7.23% of nonzero weights round to exactly zero under NVFP4 and 7.22% fall below block_max/24 (the shadowing bound), so block-outlier shadowing accounts for essentially all zeroing. Weighted relative Frobenius error: NVFP4 9.47%, FP8 per-channel 2.64%.
- 2026-10-05: Gate G0.1 PASSED, signed off by Aaron ("go"). Q1 = NVFP4 RTN W4A16 stays the primary condition and google/gemma-3-4b-pt the primary model. Evidence (results/phase0/damage_table.json): GSM8K 8-shot CoT strict 40.49% -> 33.43%, paired delta -7.05 pts, 95% CI [-9.40, -4.70], flips 13.4% correct->incorrect / 6.4% incorrect->correct; MMLU 59.62% -> 58.33%, delta -1.29 [-1.80, -0.77], flips 5.5% / 4.2%. Fully quantized KL(bf16||Q1) on the 500k-token set: mean 0.081, median 0.037, top-1 agreement 87.7%.
- 2026-10-05: Gate G0.3 PASSED. fp32 vs bf16: GSM8K +0.08 [-1.36, +1.52], MMLU +0.05 [-0.43, +0.55]; the NVFP4 losses are far outside these intervals (results/phase0/damage_table.json, damage_table_bf16_rep.json).
- 2026-10-05: The pre-registered "concentrated shift energy" claim (H3 part 1) is WITHDRAWN: the matched-noise control (C2) shows the same concentration curve as NVFP4 at layers 17 and 29, so it is a property of the SAE basis. Feature sets for steering and saliency were switched to the survival-correlation ranking before any intervention ran (results/phase2/shift/{q1,c2}_L17_summary.json, survival_L17.json).
- 2026-10-05: The boxA sprint ran as ONE burst of 8 GPUs for about 2.5 hours instead of two bursts with a smaller box in between; the two layer-29 self-trained SAEs (extended scope) were dropped so no second box was needed. All critical jobs finished with zero failures (scripts/remote/boxA_jobs.sh, /data/queue logs archived in ~/qi_archive/boxA).
- 2026-10-05: H1 is NOT supported and the first resume bullet is reworded accordingly: the 8 top-ranked layers recover 41% [9%, 74%] of the GSM8K loss and a random ordering recovers 48%; ranked minus random is never significant (results/phase1/restore_curve.json).
- 2026-10-05: H3 interventions: no 1%, 5% or 10% least-surviving feature set recovers accuracy even with oracle bf16 values; the 10% highest-energy set and the full basis recover about two thirds of the gap; the full residual recovers all of it. The deployable headline is the mean-shift bias (+2.6 [+0.2, +5.2]). The gated full-GSM8K gain run was skipped by the pre-registered gate (subset delta +0.8 < 1 point). The category-enrichment step (auto-interp of the top 1%) was not run: with no feature set carrying the loss there is no set to categorize (results/phase2/steering.json).
- 2026-10-05: H4 decision rule applied: FG-proj TIES with magnitude, KL-gradient and random channels at two of three budgets (no paired win), so the alternative third resume bullet from plan section 12 is used: channel-level protection beats whole-layer fallback at equal memory (magnitude at 92 MB = 8 layers at 1,085 MB), feature guidance does not beat magnitude (results/phase3/budget_sweep.json, memory.json).
- 2026-10-05: Evaluations on boxA pair against bf16 and NVFP4 runs from the same box (bf16_rep, q1_rep; replication within 0.4 points of boxS) because the boxS raw generations were deleted with that disk; the boxS damage table keeps its own reference (results/LEDGER.md has one block per reference).
